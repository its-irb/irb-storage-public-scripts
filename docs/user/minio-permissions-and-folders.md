# What you can do in MinIO, and how the folders are organised

## Goal

Understand which actions are allowed in MinIO (read, write, delete) and where
each kind of data lives, so you know where to look for data and where to put
it.

## The most important rule: data cannot be deleted

> **Warning — this cannot be undone.** Data stored in MinIO is *write once*:
> after it is written, it **cannot be changed or deleted**, not even by you.
> Before copying, check that you are copying the right files into the right
> folder.

This is deliberate: it protects research data from accidental loss or
modification. The technical name for this protection is **WORM** (*write once,
read many*).

## What you can do

- By default you have **read-only** access: you can **see** and **copy** data,
  but you **cannot delete** it.
- In some folders you can also **write** (add new data). See the table below.
- Copying data to MinIO **never deletes the original files** from where they
  came from. Your copy stays safe in MinIO and the original stays where it was.

## How the folders are organised

MinIO is organised in main folders (called *buckets*). These are the main
ones:

```text
MinIO
├── facility_data
│   ├── one folder per core facility   ← each core facility writes in its own folder
│   └── ...
├── internal                           ← raw data generated by your own lab
└── external                           ← raw data from outside the IRB
```

| Folder | What is stored there | Who can write | Who can read |
|---|---|---|---|
| `facility_data` | Data produced by the IRB core facilities (CF). There is one folder per core facility. | Each core facility, in its own folder. If a lab migrates its own data, it is given write access to `facility_data` for that purpose. | Everyone can view it. Biostats can read the folders of all the core facilities, because it usually analyses their data. |
| `internal` | Raw data generated by your own lab. | Your lab (read and write). | Your lab (read and write). |
| `external` | Raw data generated by core facilities outside the IRB or by other institutions. | Your lab (read and write). | Your lab (read and write). |

> Writing in a folder means you can **add** data to it. It never means you can
> delete data afterwards.

### When a core facility shares data with you

The core facility leaves the data in its own folder inside `facility_data`.
You can open and copy it from there, but you cannot change it.
